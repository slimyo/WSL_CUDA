## 0. 一张图看 2025-2026 的主线

```
工作负载变了 ──→ 架构变了 ──→ 系统变了 ──→ 硬件/kernel 变了
   (reasoning      (MoE 细粒度化      (P/D 分离+大 EP      (Blackwell/FP4

贯穿一切的主题：decode 越来越重、KV cache 越来越是中心、
              一切优化都在"算力过剩、带宽稀缺"的不对称下展开。
```

## 1. 工作负载范式：Reasoning 与 Agent 改写了推理的形状

### 1.1 Test-Time Scaling（推理时扩展）

```
o1 / DeepSeek-R1 (2025.01) 开启的范式：
  模型在回答前生成长 chain-of-thought —— 输出从几百 token 变成几千~几万 token

对 infra 的直接冲击（用 09 章的语言）：
  - decode : prefill 的时间占比大幅向 decode 倾斜 → memory-bound 问题更尖锐
  - 单请求 KV cache 随长输出持续膨胀 → 调度器要预留"未来的显存"
  - SLO 指标变化：用户对 reasoning 的 TTFT 容忍度高、对总完成时间敏感
  → 这是 P/D 分离里 D 池越配越大、KV 优化优先级压倒一切的根本原因
```

### 1.2 Agentic 工作负载

```
Agent（工具调用/多轮/多 agent）的请求模式：
  - 同一会话反复携带超长且基本不变的上下文（system prompt + 历史 + 工具结果）
  - prefix cache 命中率成为一级指标（SGLang 的 radix tree 设计动机正在于此）
  - 工具调用打断生成：会话"挂起→恢复"，KV 要么保住（占显存）要么重算（费时间）
    → 催生 KV offload 到 CPU/SSD 的分层缓存（见 §4.3）
  - 结构化输出（JSON mode）→ constrained decoding（语法约束采样）进入 serving 引擎
```

### 1.3 RL 训练中的推理（Rollout）

```
RLHF/RLVR 训练 reasoning 模型时，rollout（用当前策略生成样本）占了
训练时间的大头——而 rollout 本质上就是大规模批量推理。

→ 训练框架（verl、OpenRLHF、slime 等）直接内嵌 vLLM/SGLang 做 rollout 引擎
→ "推理引擎"不再只服务在线 serving，也是训练管线的部件
→ 新问题：权重热更新（训练几步就要把新权重同步给 rollout 引擎）、
  训推一致性（rollout 用的 kernel 与训练数值不一致会让 RL 跑偏）
面试价值：说明你理解推理引擎的第二大客户是 RL，这是 2025 起的真实岗位需求。
```

## 2. 模型架构新方向（infra 视角）

### 2.1 细粒度 MoE 成为默认架构

```
2025 年新发布的旗舰开源模型几乎全是 MoE：
  DeepSeek-V3 (256+1 expert, top-8, 671B/激活37B)
  Qwen3-235B-A22B、Kimi K2 (1T/激活32B)、gpt-oss-120B、MiniMax 系列...

infra 含义（接 16 章 EP）：
  - 总参数巨大但激活稀疏 → 权重放得下吗？→ 大 EP 跨节点摊权重
  - decode 的 batch 内不同 token 走不同 expert → GEMM 变成 grouped GEMM
    （kernel 新热点：grouped/batched GEMM、permute/unpermute 融合）
  - 通信从 all-reduce 主导变为 all-to-all 主导 → DeepEP 这类专用通信库
```

### 2.2 稀疏 Attention：从"训完再剪"到"原生可训练"

```
背景：长上下文让 prefill O(N²) 和 KV 读取都不可承受，
但传统稀疏（局部窗口/手工 pattern）掉精度。2025 年的转折是"可训练的稀疏"：

NSA (Native Sparse Attention, DeepSeek 2025.02, ACL'25 最佳论文):
  三分支：压缩(coarse token) + 选择(top-n block) + 滑窗，分支门控加权
  关键：稀疏 pattern 是端到端训出来的，且 block 粒度对齐 GPU（kernel 友好）

MoBA (Mixture of Block Attention, 月之暗面 2025.02):
  把 MoE 的 router 思想搬进 attention——每个 query 只路由到 top-k 个 KV block

DSA (DeepSeek Sparse Attention, DeepSeek-V3.2-Exp 2025.09):
  "lightning indexer" 给每个 query 挑 top-k 历史 token，
  把核心 attention 复杂度从 O(L²) 压到 O(L·k) → 官方 API 长上下文降价 50%+

面试怎么用：能讲清"稀疏 attention 的难点不在数学在 kernel
（gather 的非连续访存、block 对齐、和 paged KV 的组合）"就是加分项。
```

### 2.3 线性 / 混合 Attention 卷土重来

```
线性注意力（RNN 式状态递推，KV cache 是 O(1) 常数大小）在 2024 前精度不行，
2025 年靠"混合架构"落地——大部分层用线性，少数层保留全量 attention：

  Mamba-2 / SSM 系：状态空间模型，与 attention 对偶 (SSD 理论)
  MiniMax-M1 (2025.06): lightning attention 混合，1M 上下文
  Qwen3-Next (2025.09): Gated DeltaNet + 标准 attention 混合 (3:1)
  Kimi Linear (2025.10): KDA (Kimi Delta Attention) 混合

infra 含义：
  - 线性层没有 KV cache，只有固定大小的 state → 显存模型完全不同
  - 调度器/PagedAttention 假设"每 token 增量缓存"——混合架构打破了这个假设
    （serving 引擎要同时管理 paged KV 和 per-request state，两套显存账本）
  - decode 算术强度结构改变：线性层 state 更新是纯 GEMV/elementwise
```

### 2.4 MLA 与 MTP 的扩散

```
- MLA（11 章）从 DeepSeek 专属走向行业选项；面试必会矩阵吸收
- MTP (Multi-Token Prediction, DeepSeek-V3 内置):
  模型自带"预测后续多个 token"的轻量 head
  → 推理时天然当 speculative decoding 的 draft 用（接受率高达 85%+）
  → spec decode 从"外挂小模型"演化为"模型原生自带"（vLLM/SGLang 已支持 MTP）
  → EAGLE-3 (2025) 是外挂路线的 SOTA，与 MTP 思想合流
```

## 3. 硬件：Blackwell 时代与"不对称缩放"

```
Blackwell (B200 / GB200 NVL72, 2024 发布 2025 上量):
  - tcgen05 + Tensor Memory（见 tensor_cores_intro §7）
  - 原生 NVFP4/MXFP4 → W4A4 推理（见 15 章 §5）
  - GB200 NVL72：72 张 GPU 用 NVLink 5 (1.8 TB/s) 连成一个机柜级 NVLink 域
    → "节点"的边界从 8 卡变成 72 卡 → TP/EP 的可用范围扩大一个量级
    → 大 EP + P/D 分离的部署形态正是为这种机器设计的
  - GB300 (2025 下半年): 更大 HBM3e；下一代 Rubin 预计 2026

关键认知——不对称缩放 (asymmetric scaling)，面试高频论点：
  代际间 Tensor Core FLOPS 增长 >> HBM 带宽增长 >> CUDA core/SFU 增长
  → ridge point 不断右移，越来越多 kernel "天生 memory-bound"
  → 软件含义：非 matmul 操作越来越贵（FA4 重写 softmax 的原因）、
    低精度（FP8→FP4）是吃满 TC 的唯一途径、fusion 重要性逐代上升
国产侧：昇腾 910B/910C、寒武纪等的推理适配是国内大厂真实岗位需求，
vLLM-Ascend、MindIE 等生态值得知道名字。
```

## 4. 推理系统：2025-2026 的格局

### 4.1 P/D 分离 + 大 EP 成为旗舰部署标配

```
DeepSeek 推理系统公开（2025.02 open infra week）后成为参照系：
  - Prefill 池与 Decode 池分离（13 章），各自不同的并行策略
  - Decode 池用跨节点大 EP（一个 expert 副本服务整个池）
  - 配套开源全家桶：FlashMLA(MLA decode kernel)、DeepEP(MoE 通信)、
    DeepGEMM(FP8 grouped GEMM)、EPLB(expert 负载均衡)、3FS(存储)
NVIDIA Dynamo (GTC 2025): P/D 分离的开源编排层
  （PD-aware 路由、KV-aware 调度、NIXL 传输库），定位 "数据中心级推理 OS"
```

### 4.2 引擎演进：vLLM V1 / SGLang

```
vLLM V1 (2025): 核心重构——
  调度器统一 prefill/decode（chunked prefill 默认开）、zero-overhead 前缀缓存、
  CPU 调度与 GPU 执行重叠、torch.compile 集成、FlashInfer 做 attention backend
SGLang: radix cache + overlap scheduler + 大规模 P/D+EP 部署的先行者
共同趋势：调度 overhead 进入 μs 级竞争，CPU 侧也成了优化对象
（这就是 17 章 CUDA Graph / 异步调度重要性的来源）
```

### 4.3 KV Cache 全局化/分层化

```
KV cache 从"单卡显存里的 tensor"变成"集群级的分布式存储系统"：
  HBM → CPU DRAM → 本地 SSD → 远端存储池 的多级层级
  Mooncake (Kimi, FAST'25 最佳论文): KV-centric 架构 + 全局 KV pool
  LMCache / NIXL / Dynamo KV manager: KV 的存取、传输、复用中间件
  驱动力：agent 会话复用 + P/D 传输 + 长上下文 → "KV 即资产"
```

## 5. Kernel 开发范式：DSL 百花齐放与 AI 写 Kernel

### 5.1 Python 化的高性能 kernel DSL（2025 爆发）

| DSL | 出处 | 一句话定位 |
|------|------|------|
| **CuTe-DSL** | NVIDIA (2025) | CuTe 的 Python 版——Python 写 layout/MMA，性能≈C++ CUTLASS，**FA4 用它实现** |
| **Gluon** | OpenAI Triton 团队 (2025) | Triton 的"低层方言"：暴露 layout/异步流水，夺回 Triton 让渡的控制权 |
| **TileLang** | 北大/TileAI (2025) | tile 级 DSL，论文显示部分 kernel 超 Triton；国内关注度高 |
| **ThunderKittens** | Stanford Hazy Research | C++ 嵌入式 tile 框架，"kernel 就该长成 tile 操作"的极简示范 |
| **Helion** | Meta/PyTorch (2025) | 更高层的 PyTorch-native kernel DSL，编译到 Triton |

```
怎么看：所有 DSL 都在回答同一个问题——
"Hopper/Blackwell 的异步硬件（TMA/wgmma/tcgen05/TMEM）太难手写了，
 如何在不掉性能的前提下把 tile/layout/流水线抽象出来？"
面试不需要会写每个 DSL，但要能讲出这条共同主线（接 14 章的选型轴）。
LeetCUDA 映射：kernels/cutlass/cute_dsl/ 已有 CuTe-DSL 示例。
```

### 5.2 AI 生成 Kernel

```
KernelBench (Stanford, 2025) 等基准 + LLM agent 自动写/调 CUDA kernel 的尝试
（含 NVIDIA 用 LLM 生成 attention kernel 的实验）：
  当前状态：elementwise/简单 fusion 可用，复杂 kernel 仍远逊专家
  趋势：kernel 工程师的工作重心向"性能建模、验证、评审 AI 产出"偏移
面试价值：被问"怎么看 AI 写算子"时，有数据点、有判断（而不是恐慌或吹捧）。
```

## 6. 量化前沿：FP8 训练化、FP4 推理化

```
2025-2026 的精度阶梯（接 07/15 章）：
  训练: BF16 → FP8 混合精度（DeepSeek-V3 首个大规模 FP8 训练的旗舰开源模型，
        细粒度 tile/block-wise scaling + 关键路径保留 BF16/FP32）
  推理: FP8 W8A8 成为 H100 上的默认推荐
        FP4 上量：gpt-oss (2025.08) 直接以 MXFP4 权重发布；
        NVFP4 W4A4 在 Blackwell 上由 TRT-LLM/ModelOpt 推进
  KV:   FP8 KV cache 普及，INT4/混合精度 KV 研究活跃
  QAT 回潮：Gemma 3 QAT 版证明"训练时就为低精度做准备"路线可行

值得引用的判断：量化的重心从"事后压缩"（PTQ 救火）
转向"原生低精度"（训练即低精度，推理零转换）。
```

## 7. 其他值得知道名字的方向

```
- Diffusion LLM：并行生成多 token（Gemini Diffusion 实验, 2025），
  若成立将颠覆"自回归 decode = memory-bound"的全部前提——目前看仍是早期
- Attention-FFN 分离（MegaScale-Infer, 字节 2025）：MoE decode 中把 attention
  和 FFN 拆到不同 GPU 池、各自 batch——P/D 分离思想在"层内"的再应用
- 长上下文外推：YaRN、context parallel 推理（Ring Attention 工程化）
- 端侧/边缘推理：llama.cpp 生态、NPU 适配、3B 级小模型 + 投机解码组合
- 推理专用芯片：Groq(LPU)/Cerebras 的超高单流 decode 速度，
  本质是"用 SRAM 换 HBM"对 memory wall 的另一种回答（面试聊架构观很好用）
```

## 10. 自测 / 面试题
